The `app/` directory follows Next.js App Router conventions where each feature folder is a route segment: UI pages (`content`, `ideas`, `publishing`, `calendar`, `analytics`, etc.) render inside the root `layout.tsx` WorkspaceLayout, mutate state via co-located server actions under `actions/`, and call backend services through sibling `api/` route handlers grouped by domain (`ai/*`, `media/*`, `publishing/*`). Cross-cutting concerns are centralized: the root layout supplies global fonts, Tailwind theme, and CSS animations; the `publishing/engine/providers/` registry exposes a uniform interface consumed by both the publishing center page and the `api/publishing/process` route so scheduled posts dispatch identically whether triggered from the UI or a cron-like poller. All data persistence goes through Prisma, which the landing page, content actions, and publishing engine share.

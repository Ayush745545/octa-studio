Routes are organized by domain under `app/api/` following Next.js App Router conventions, each route file exporting HTTP handlers (`GET`/`POST`/`DELETE`) that return `NextResponse.json` or redirects.

- `ai/` — Text generation at `ai/generate/route.ts` proxies to an OpenAI-compatible LLM via `fetch` using `AI_BASE_URL`/`AI_MODEL` env vars; image/video generation at `ai/image/route.ts` and `ai/video/route.ts` use a shared `ComfyUIClient` from `@/lib/ai/comfyui` with workflow builders from `@/lib/ai/workflows/*`, health-checking the engine before submitting long-running jobs and polling until completion.
- `media/` — CRUD over uploaded assets: `route.ts` lists/creates media records via Prisma; `[id]/route.ts` deletes a media row and its underlying file from `public/uploads`; `upload/route.ts` accepts `multipart/form-data`, validates MIME type against an allowlist and size cap, writes files to disk under `public/uploads`, and persists metadata through Prisma.
- `publishing/` — LinkedIn OAuth flow split across `linkedin/connect/route.ts` (redirects to LinkedIn authorization) and `linkedin/callback/route.ts` (exchanges code for tokens, fetches user info, upserts `publishingChannel` in Prisma); `process/route.ts` is a cron endpoint guarded by a `Bearer CRON_SECRET` token that delegates work to `@/app/publishing/engine/process-scheduled`.

Dependency direction is one-way: routes depend on shared libraries (`@/lib/prisma`, `@/lib/ai/*`, `@/app/publishing/engine/*`) but never the reverse. All external services (LLM, ComfyUI, LinkedIn, Prisma) are accessed via environment variables rather than hard-coded configuration.

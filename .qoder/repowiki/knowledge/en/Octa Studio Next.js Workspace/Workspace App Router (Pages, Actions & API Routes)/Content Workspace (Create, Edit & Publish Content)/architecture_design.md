Organized as a Next.js App Router segment under `app/content/` with three route segments: `page.tsx` renders the content library list via a server component querying Prisma; `[id]/page.tsx` is a server component that loads a single content record (with related idea, publications, media) and composes UI components (`ContentEditor`, `ContentStatusSelector`, `PublicationSelector`, `PublishButton`) while delegating mutations to server actions; `new/page.tsx` is a client component form that calls `createContent` and redirects. All data mutations live in `actions/` as `'use server'` functions (`create-content`, `update-content`, `update-content-status`, `schedule-content`, `reschedule-content`, `cancel-schedule`, `publish-content`, `create-publication`, `create-content-from-idea`). Each action validates inputs, enforces content status transitions (DRAFT → READY/SCHEDULED, PUBLISHED is terminal), uses Prisma transactions where multiple rows must stay consistent (e.g., scheduling updates both `content` and `publication`), calls `revalidatePath` on affected routes, and delegates actual publishing to `@/app/publishing/engine/publish`. Dependency direction is one-way: pages import actions and shared UI components; actions import Prisma and the publishing engine but never import page components.

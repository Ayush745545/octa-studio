The module is organized by feature area under `components/`, each folder owning a cohesive set of React server/client components:
- `layout/` provides the shared `WorkspaceLayout`, `WorkspaceSidebar`, and `WorkspaceTopBar` that wrap every app view; `workspace-layout.tsx` composes sidebar + top bar + main and manages sidebar collapse state.
- `calendar/` is the largest feature: `calendar-workspace.tsx` is the root orchestrator holding week navigation, media drawer, create-post modal, toast, and drag-and-drop state, then delegates rendering to `calendar-view`, `calendar-toolbar`, `media-drawer`, `media-picker-modal`, `media-panel-closed`, `create-post-modal`, and `toast`. It calls server actions (`reschedulePublication`) and `/api/media/upload` for mutations.
- `content/`, `ideas/`, `publishing/`, and `ai-studio/` each contain small focused components (editor, status selector, publication selector, publish button, new idea form/modal, turn-into-content button, post-preview panel).
- `landing-client.tsx` is a standalone Next.js client component used as the marketing landing page, built from self-contained sections (hero, GSAP-powered calendar showcase, pricing, FAQ, CTA banner) and does not depend on the workspace layout.
Dependency direction is one-way: feature folders import from `layout/`; nothing in `layout/` imports back into features. Cross-feature communication happens via props passed down from the workspace root (e.g. `connectedChannels`, `posts`) rather than shared stores.
